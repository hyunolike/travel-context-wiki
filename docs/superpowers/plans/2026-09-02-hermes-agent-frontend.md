**Goal:** 계획 2가 만든 서버 위에 화면 둘을 얹어, 인용을 눌러 근거 문서를 여는 형태로 만든다. 설명이 어디에서 왔는지를 **클릭해서 확인할 수 있게** 하는 것이 이 계획의 전부다.

**Architecture:** Next.js App Router. 프론트는 **에이전트 서버 하나만** 부른다 — 한적을 직접 부르지 않는다(스펙 §4). 코스 화면은 사실과 설명을 **따로** 받아 사실이 오는 즉시 그리고, 설명은 도착하면 붙인다.

**Tech Stack:** Next.js 16 (App Router), React 19, TypeScript, Tailwind CSS 4, zod, Vitest + Testing Library, pnpm

**Spec:** `docs/superpowers/specs/2026-08-31-hermes-agent-repo-design.md` (§6 화면, §7 데모 코스, §4 엔드포인트)

**선행 계획:** `2026-08-31-hermes-agent-core.md`, `2026-09-01-hermes-agent-api.md` (둘 다 완료)

## 스펙이 틀렸던 지점 — 이 계획이 먼저 고친다

스펙 §6.1은 이렇게 적혀 있다.

> **503이면 설명 블록만 사라진다.** 코스는 그대로 읽힌다 — 한적의 규칙 기반 문구가 이미 각 항목에 붙어 있기 때문이다.

**지금 API로는 불가능하다.** `POST /agent/explain` 하나가 설명과 `facts`를 함께 돌려주고, 실패는 전부 503이다. LLM만 실패해도 응답 전체가 503이므로 프론트에는 코스를 그릴 `facts`가 없다. "설명 블록만 사라진다"가 아니라 **화면 전체가 사라진다.**

세 가지 길이 있었다.

| 안 | 문제 |
|---|---|
| 프론트가 한적을 직접 호출 | 스펙 §4가 명시적으로 배제한다 — `facts`를 함께 돌려주는 이유가 "그래야 한적을 직접 부르지 않는다"였다 |
| `explain`이 LLM 실패 시 200 + `explanation: null` | 확립된 계약(모든 실패는 503)을 바꾼다. `ApiErrorHandler`와 그 테스트가 전부 흔들린다 |
| **사실만 주는 엔드포인트를 추가한다** | 계약을 바꾸지 않고, 화면이 사실과 설명을 따로 받는다 |

세 번째를 택한다. **부수 효과가 본론보다 낫다** — 코스가 LLM 왕복(3~5초)을 기다리지 않고 즉시 그려진다. progressive enhancement가 말로만이 아니라 실제로 그렇게 동작한다.

## Global Constraints

- **레포**: `hermes-agent`, 브랜치 `main`. 프론트는 `frontend/`.
- **프론트는 에이전트 서버만 부른다.** 한적 주소를 프론트가 알면 안 된다.
- **어떤 키도 프론트에 내려가지 않는다.** `NEXT_PUBLIC_*`은 에이전트 서버 주소 하나뿐이다.
- **등급 4단계를 발명하지 않는다.** `RELAXED`/`NORMAL`/`CROWDED`/`VERY_CROWDED` 외의 값은 없고, 한국어 라벨은 여유·보통·혼잡·매우혼잡이다(`records/congestion/grade-policy.json`). 색은 프론트의 것이지만 **단계 수와 라벨은 아니다.**
- **응답을 신뢰하지 않는다.** 서버 응답은 zod로 파싱한다. 파싱 실패는 렌더 실패로 드러내고 조용히 빈 화면을 만들지 않는다.
- **FSD를 쓰지 않는다.** 화면이 둘이다. 한적 프론트의 feature-sliced 구조는 여기서 규모에 맞지 않는다.
- **테스트는 네트워크를 타지 않는다.** `fetch`를 주입하거나 스텁한다.
- **커밋은 태스크마다.** 각 태스크 끝에 `pnpm typecheck && pnpm test`가 통과해야 한다.

## Task 1 — 사실만 주는 엔드포인트 (서버)

`GET /agent/facts/{courseUuid}` → `{ courseUuid, facts }`, 200. 한적 실패면 503 `EXPLANATION_UNAVAILABLE`.

`CourseExplainer`가 아니라 `FactsSource`를 직접 부른다 — LLM을 타지 않는 것이 이 엔드포인트의 존재 이유다. 설명 캐시도 건드리지 않는다.

**테스트**
- [ ] 사실을 200으로 돌려준다. `facts`가 문자열이 아니라 JSON 객체다(`RawValue`).
- [ ] LLM 프로바이더를 **한 번도 부르지 않는다** — 페이크 프로바이더의 호출 수가 0.
- [ ] 한적이 죽으면 503 `EXPLANATION_UNAVAILABLE`.
- [ ] 깨뜨려 확인: `CourseExplainer`를 경유하도록 바꾸면 "프로바이더 호출 0" 테스트가 실패한다.

## Task 2 — 프론트 골격

`frontend/`에 Next 16 + TS + Tailwind 4 + Vitest. `NEXT_PUBLIC_AGENT_BASE_URL`(기본 `http://localhost:8080`).

데모 코스 3개는 `demo-courses.ts` 상수다. **uuid는 아직 없다** — 한적에 코스를 만들어야 정해진다. 그때까지 빈 배열이고, 홈은 "데모 코스가 아직 설정되지 않았습니다"를 띄운다. 가짜 uuid를 채워 두면 화면은 뜨는데 전부 503이 나고, 그게 서버 문제인지 uuid 문제인지 구분되지 않는다.

**테스트**
- [ ] 데모 목록이 비면 홈이 안내 문구를 낸다. 코스 카드를 그리지 않는다.
- [ ] 스펙 §7의 세 종류(대안 있음 / 대안 없음 / 다른 날짜 추천)가 상수의 주석이 아니라 타입으로 남는다 — `kind` 필드를 요구한다.

## Task 3 — 클라이언트와 스키마

`schema.ts`가 서버 응답을 해석하는 **유일한 지점**이다. `facts`의 필드는 서버 `FactsProjection`이 확정한 것을 그대로 따른다.

**테스트**
- [ ] 정상 응답을 파싱한다.
- [ ] `grade`에 모르는 값이 오면 파싱이 **실패한다**. 조용히 통과시키면 색이 없는 항목이 그려지고, 그 화면은 등급 체계가 깨진 것을 감춘다.
- [ ] 503 본문(`{"code":"EXPLANATION_UNAVAILABLE"}`)을 예외가 아니라 값으로 돌려준다 — 설명 없음은 화면이 다뤄야 할 정상 상태다.
- [ ] 깨뜨려 확인: `grade`를 `z.string()`으로 바꾸면 위 테스트가 실패한다.

## Task 4 — 코스 화면

위에서부터 제목, 혼잡도 감소율, 방문 순서(등급 색 + `timeLabel` + 이동 시간), 그 아래 설명 블록.

- 사실은 **서버 컴포넌트**가 받아 즉시 그린다.
- 설명은 **클라이언트 컴포넌트**가 따로 받아 붙는다. 오는 동안 자리를 비워 둔다.
- 설명이 503이면 그 블록만 사라진다. 코스는 그대로 읽힌다 — 이제 진짜로.

**테스트**
- [ ] 설명이 503이어도 방문 순서가 전부 렌더된다.
- [ ] 등급 색이 4단계 전부 서로 다르다.
- [ ] 인용 칩은 `citations` 배열에서만 나온다 — 응답에 없는 경로는 칩이 되지 않는다.
- [ ] 깨뜨려 확인: 설명 실패 시 페이지 전체를 throw하게 바꾸면 첫 테스트가 실패한다.

## Task 5 — 인용 시트

칩을 누르면 `GET /agent/context/{path}`의 본문이 시트로 올라온다. 화면을 떠나지 않는다.

**테스트**
- [ ] 칩을 누르면 그 경로의 문서를 요청한다.
- [ ] 문서가 404면 시트가 "이 문서는 번들에 없습니다"를 낸다 — 빈 시트가 아니다.
- [ ] Esc와 바깥 클릭으로 닫힌다.

## Task 6 — 근거 열람 화면

좌측 문서 목록(경로 + 바이트), 우측 본문. 상단에 **번들 전체 크기**를 낸다.

**위키 전체가 아니라 번들 9개 문서만.** 이 화면이 증명하려는 것은 "LLM이 볼 수 있었던 전부가 이만큼"이라는 것이고, 총 바이트를 노출하는 것이 "벡터 검색이 필요 없는 크기"라는 주장을 화면이 스스로 보이게 하는 방법이다.

**테스트**
- [ ] 목록이 `GET /agent/context`의 항목 수와 같다.
- [ ] 총 바이트가 각 항목의 합과 같다.
- [ ] 문서를 고르면 본문이 바뀐다.

## 이 계획이 하지 않는 것

- **역방향 목록**("이 문서를 인용한 설명") — 설명 이력을 남기려면 저장소가 생기고, "DB 없음" 전제가 깨진다(스펙 §6.2).
- **코스 생성 화면** — 쇼케이스에 코스를 만드는 자리는 없다(§7).
- **배포** — Vercel은 계획 4다.
- **데모 uuid 확정** — 한적에 코스를 만들어야 한다. 그 전까지 홈은 빈 상태를 정직하게 보여 준다.

## Self-Review

- Task 1이 서버를 건드리는데 이 계획은 프론트 계획이다. 그래도 여기 두는 이유: 이 엔드포인트가 필요하다는 것은 화면을 설계하고서야 드러났고, 서버 쪽에는 이걸 요구하는 사용자가 없다.
- 데모 uuid가 빈 상태로 끝난다. 화면 둘은 완성되지만 **데모는 완성되지 않는다.** 한적 코스가 생겨야 닫힌다.
