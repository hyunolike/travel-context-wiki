## 0. 이 문서가 대체하는 것

2026-08-17 설계문은 Hermes를 **한적 VM에 얹는 헤드리스 API**로 그렸다. 이후
"프론트·서버·AI를 새 레포에서 구분해 짓는다"로 방향이 바뀌면서 다섯 항목이 대체된다.
나머지는 그 문서가 여전히 정본이다.

| 항목 | 2026-08-17 | 이 문서 |
| --- | --- | --- |
| 코드가 사는 곳 | 명시 없음 | 신규 레포 `hermes-agent` |
| 한적 호출 | 데이터 흐름은 1회, 픽스처는 4회 | **3회, 왕복 2회** (§3) |
| 노출 | 엔드포인트 1개 | **4개** — 근거 열람이 추가된다 (§4) |
| 사용자 접점 | 없음(헤드리스) | **화면 2개** (§6) |
| 배포 | 한적 VM compose + Caddy 내부 리스너 | **Cloud Run + Vercel**, 한적 변경 0건 (§8) |

§6.2 LLM 파라미터, §6.3 프롬프트 캐싱, §8 실패 처리, §12 하지 않는 것은
그대로 유효하며 이 문서가 반복하지 않는다. 한 가지만 정정한다 —
**`max_tokens`는 4,096이 아니라 8,192**다. 그 한도가 thinking과 응답 텍스트를
합쳐서 덮는데 이 모델은 thinking이 기본 ON이라, 4,096은 답이 잘릴 위험이 있다.
이 판단은 2026-08-19 `log.md`에 이미 기록됐다.

**§5의 번들 실측도 갱신한다.** 7,208바이트는 2026-08-19 수정 이전 값이다.
canonical 페이지 넷을 고치고 `concepts/congestion-diagnosis.md`와
`decisions/keep-llm-out-of-ranking.md`를 추가하면서 **9개 문서 15,681바이트**가 됐다.
결론은 바뀌지 않는다 — 여전히 통째로 넣는 크기고, 캐시 가능 최소 접두사 512토큰을
크게 넘는다. 벡터 검색 없음을 유지한다.

§13의 미해결 2번(번들 조립 스크립트 없음)은 **해소됐다.** `scripts/build-bundle.sh`가
2026-08-19에 생겼고, 두 번 실행이 바이트 단위로 같은지를 smoke가 검사한다.

## 1. 무엇을 만드는가

**한적의 부가 기능이 아니라 위키의 쇼케이스다.**

"결정론적 백엔드가 고른 코스를, 보존된 근거를 인용해 설명한다"는 이 저장소의 주장을
**클릭해서 확인할 수 있는 형태**로 만든다. 인용을 눌러 근거 문서를 여는 화면은
여행 앱에는 어색하지만 쇼케이스에는 핵심이다.

이 규정에는 대가가 따르고, 알고 고른다.

- **한적 사용자는 이 화면을 못 본다.** 코스를 실제로 보는 자리에 설명이 붙지 않는다.
- 한적이 이미 가진 코스 상세 UI를 재사용할 수 없다. 처음부터 만든다.
- 운영할 프론트가 하나 늘어난다.

얻는 것은 이렇다.

- **한적 레포에 PR 0건.** 08-17 설계는 `infra/startup.sh.tftpl`의 Caddyfile 변경이
  1건 필요했다. 이 구조는 0건이다.
- 스택·배포·릴리스가 한적과 완전히 분리된다.
- 평가를 레포 루트의 일급 시민으로 둘 수 있다.

## 2. 레포 구조

```
hermes-agent/
├── frontend/                          Next.js · 화면 두 개
│   ├── app/course/[uuid]/             코스 설명 화면
│   ├── app/evidence/                  근거 열람 화면
│   └── lib/api.ts                     server 만 호출한다
│
├── server/                            Gradle 모듈 하나
│   ├── src/main/kotlin/com/hermes/
│   │   ├── explain/                   설명 루프 — facts → 프롬프트 → 호출 → 검증
│   │   │   └── presentation/          여기만 HTTP를 안다
│   │   ├── facts/                     한적 클라이언트
│   │   ├── context/                   번들 적재 · 프롬프트 조립 · 인용 검증
│   │   ├── llm/                       프로바이더 어댑터 · 재시도 · 타임아웃
│   │   └── shared/
│   └── src/main/resources/prompts/    프롬프트 · 스키마 · 번들
│
├── harness/                           평가 — 서버를 띄우지 않고 돈다
├── infra/                             Terraform · 배포 워크플로
└── docs/
```

루트는 한적 레포와 같은 모양이다(`backend`가 `server`로 바뀌는 것뿐).
`harness/`도 새 발명이 아니다 — 한적과 이 위키가 이미 "단위 테스트가 아닌 검사"를
담는 자리로 쓰고 있다. 평가는 돈이 들고 비결정적이라 `./gradlew test`에 섞이면 안 된다.

### 2.1 단일 Gradle 모듈

`kotlin-spring-modulith-template`과 `hanjeok/backend` 둘 다 `settings.gradle.kts`에
`include(...)`가 없다. 단일 모듈이고, 모듈 경계는
`com.hanjeok.course/{application,domain,presentation}`처럼 **패키지로 표현하고
Modulith 테스트가 강제**한다. 템플릿 README의 문장 그대로다 —
"Package boundaries **are** module boundaries, enforced by tests."

멀티모듈은 `settings.gradle` 관리, 모듈 간 리팩터링 지연, 의존 배선을 늘리는데,
그 값은 독립 빌드나 아티팩트 배포가 필요해질 때 생긴다. 지금은 그럴 이유가 없다.

### 2.2 지켜야 하는 성질

**헤르메스는 웹 서버가 아니라 에이전트다.** 사실을 모으고, 프롬프트를 조립하고,
모델을 부르고, 돌아온 인용을 번들과 대조하는 것 — 그중 어느 것도 HTTP를 필요로 하지
않는다. 그래서 `explain/presentation` 바깥의 어떤 패키지도 HTTP를 몰라야 한다.

이 규율이 지켜지면 **`harness/`가 실제 경로를 잰다.** presentation을 건너뛰고
application 층을 직접 불러 돌리므로, 평가가 통과한 프롬프트 조립과 인용 검증이
운영에서 도는 것과 같은 코드다. 평가를 컨트롤러 뒤에 두면 픽스처 흉내만 내게 되고
정작 인용 검증은 평가 밖에 남는다.

**물리적 차단이 아니라 규율이라는 점이 이 선택의 대가다.** 별도 컴파일 단위였다면
역참조가 컴파일 에러였을 것을 여기서는 Modulith 테스트가 잡는다. 테스트를 지우면
경계도 사라진다. 그래서 그 테스트는 지워도 되는 테스트가 아니라 **설계의 일부**다.

## 3. 한적 호출 — 3회, 왕복 2회

`harness/fixtures/course-explanation-request.json`의 네 응답이 실제로 무엇을 더
주는지 재봤다.

| 호출 | 코스 응답에 없는 것 | 판정 |
| --- | --- | --- |
| `GET /api/v1/courses/{uuid}` | 기준. `targetDate`, `items[]`(등급·`timeLabel`·규칙 문구·이동시간), `congestionReductionRate`, `recommendedDate` | 유지 |
| `GET /api/v1/attractions/{id}` | `area` **하나뿐** | **버린다** |
| `GET /api/v1/attractions/{id}/congestion?date=` | `concentration`, **`percentile`**, `betterDates`, `dailyForecasts` | 유지 |
| `GET /api/v1/attractions/{id}/alternatives?date=&radius=` | **`score`**, `relationScore`, `distanceKm`, `concentration` | 유지 |

`attractions/{id}`는 지역명 하나를 받으려고 왕복을 하나 더 쓴다. 값이 없다.

나머지 둘은 버릴 수 없다. **`percentile`이 없으면
`concepts/congestion-diagnosis.md`를 설명할 근거가 없다** — 등급이 원값이 아니라
같은 날 전국 백분위에서 나온다는 게 그 문서의 핵심이다. **`score`가 없으면
`concepts/alternative-scoring.md`의 0.4/0.4/0.2 가중치를 설명할 수 없다.**
번들에 두 문서를 넣어 놓고 근거 사실을 주지 않으면 지어내라고 시키는 것과 같다.

호출 형태는 **코스 1회 → 그 응답에서 파생한 2회 병렬**이다. `date`는 `targetDate`에서,
대상은 `items[0].attractionId`에서 나온다. 코스 첫 항목이 항상 목적지인 것은
`CourseRoutePolicy.bestOrder`가 `listOf(originId) + best`를 반환하기 때문이고,
이 사실은 `concepts/travel-context-layer.md` 수정(2026-08-19) 때 확인됐다.

따라서 지연은 4왕복이 아니라 **2왕복**이다.

## 4. 서버가 노출하는 것

| 엔드포인트 | 쓰임 | 비고 |
| --- | --- | --- |
| `POST /agent/explain` | `{ courseUuid }` → `{ explanation, citations, facts, generatedAt, model }` | **`facts`를 함께 돌려준다** — 프론트가 코스를 그리려면 필요하고, 그래야 한적을 직접 부르지 않는다 |
| `GET /agent/context` | 번들 문서 목록 — 경로, 제목, 분류, 바이트 | 근거 화면 좌측 목록 |
| `GET /agent/context/{path}` | 문서 하나의 본문 — **LLM에 보낸 바이트 그대로** | 번들에 없는 경로는 404 |
| `GET /actuator/health` | 기동 확인 | 번들 적재 실패 시 DOWN — 근거 없이 뜨는 것을 막는다 |

실패 응답은 08-17 설계문 §8의 표를 그대로 따른다. `stop_reason == "refusal"`
분기를 포함한다.

## 5. 인용은 번들 사본을 가리킨다

화면을 붙이면 곧바로 부딪히는 질문 — 인용 칩을 누르면 어디로 가야 하나.

**GitHub 링크는 쓰지 않는다.** 그건 설명이 근거한 문서가 아니라 *오늘의* 문서를 연다.
위키는 계속 고쳐지므로, 설명이 인용한 문장이 그 페이지에 없을 수 있다.

서버는 이미 번들을 통째로 메모리에 들고 있다. 그것을 읽기 전용으로 노출하면
**인용의 진실성과 근거 열람 화면이 동시에 해결된다.** 추가 저장소도 동기화도 없다.

부수 효과가 더 크다. `context` 패키지가 인용 경로를 번들 목록과 대조할 수 있으므로,
LLM이 번들에 없는 문서를 인용하면 **응답을 내보내기 전에** 잡힌다.
08-17 설계문 §10의 harness 검사 "인용 유효성"이 테스트가 아니라 **런타임 방어선**이 된다.

## 6. 화면

### 6.1 코스 설명 — `/course/[uuid]`

위에서부터 코스 제목과 혼잡도 감소율, 방문 순서 목록(등급 색 + `timeLabel` + 이동시간),
그 아래 설명 블록. 설명 블록 하단에 인용 칩이 붙고, 누르면 근거 문서가 시트로 올라온다.
화면을 떠나지 않는다.

- **등급 색은 발명하지 않는다.** 여유·보통·혼잡·매우혼잡은
  `records/congestion/grade-policy.json`의 4단계를 그대로 쓴다.
- **칩은 `citations` 배열이다.** LLM이 실제로 인용한 것만 뜬다.
- **503이면 설명 블록만 사라진다.** 코스는 그대로 읽힌다 — 한적의 규칙 기반 문구가
  이미 각 항목에 붙어 있기 때문이다(08-17 §8의 progressive enhancement).

### 6.2 근거 열람 — `/evidence`

좌측에 번들 문서 목록, 우측에 본문. 분류는 `packages/hanjeok/context-bundle.json`의
것을 그대로 쓴다 — 화면이 위키 구조를 새로 발명하지 않으므로 번들이 바뀌면 화면이
저절로 따라온다.

**위키 전체가 아니라 번들에 담긴 9개 문서만** 보여 준다. 그게 이 화면이 증명하려는
것이다 — LLM이 볼 수 있었던 전부가 이만큼이라는 것. 파일 크기를 함께 노출해서
"벡터 검색이 필요 없는 크기"라는 주장을 화면이 그대로 보이게 한다.

"이 문서를 인용한 설명" 역방향 목록은 **MVP에 넣지 않는다.** 설명 이력을 남기려면
저장소가 생기고, 그러면 "DB 없음"이라는 전제가 깨진다.

## 7. 데모 코스는 고정한다

쇼케이스에는 코스를 만드는 화면이 없다. 코스 uuid를 사용자에게 입력받지 않고
**한적에 미리 만들어 둔 코스 몇 개를 고정으로 둔다.**

- 목록은 `frontend/`의 설정 상수로 둔다. 서버는 uuid를 특별 취급하지 않는다 —
  데모 코스도 다른 코스와 똑같이 §3의 3회 호출로 처리된다.
- **사실은 여전히 한적에서 실시간으로 온다.** 응답을 녹화해 두지 않는다.
  녹화본을 폴백으로 쓰면 "사실의 출처는 항상 백엔드"라는 규정이 조용히 깨진다.
- **개수는 3개**로 시작한다. 수가 아니라 종류가 기준이다 — 서로 다른 설명을 요구하는
  코스여야 한다. (a) 목적지가 매우혼잡이고 대안이 붙은 코스, (b) 대안이 비어 있는 코스,
  (c) `recommendedDate`가 다른 날을 가리키는 코스. 셋은 각각 번들의 다른 문서를
  인용해야 하므로, 인용 검증이 실제로 작동하는지가 데모에서 드러난다.
  (b)가 특히 중요하다 — 대안이 비었다는 것은 점수가 후보를 탈락시킨 게 아니라
  **조용한 실내 후보가 애초에 없었다**는 뜻이고, 이 구분을 틀리게 설명하는 것이
  `concepts/alternative-scoring.md`가 막으려는 오류다.

**따라온 결과 하나**: 데모는 한적 백엔드와 그 코스 레코드가 살아 있어야 동작한다.
한적이 내려가면 화면은 비고, 코스가 삭제되면 데모가 깨진다. 이건 결함이 아니라
"사실은 백엔드에서만 온다"를 지킨 대가이고, 깨졌을 때 조용하지 않도록
고정 uuid 각각에 대한 도달성 검사를 `harness/`에 둔다.

## 8. 배포

| 항목 | 값 |
| --- | --- |
| 프론트 | Vercel. 한적 프론트가 이미 Vercel이라 절차가 같다 |
| 서버 | Cloud Run. 상태·DB가 없어 0으로 스케일다운된다 |
| 한적 접근 | 공개 API를 서버-서버로 호출. 브라우저가 한적을 직접 부르지 않으므로 **CORS 변경 0건** |
| 번들 | CI에서 위키를 체크아웃해 `scripts/build-bundle.sh`를 돌리고 `server/src/main/resources/prompts/`에 넣어 이미지에 굽는다. 런타임에 clone하지 않는다 |
| 시크릿 | LLM 키는 Secret Manager. 프론트에는 어떤 키도 내려가지 않는다 |

Cloud Run으로 가면 08-17 §9의 세 가지 문제가 함께 사라진다 — `mem_limit` 산정,
블루-그린 활성 색 지정, Caddyfile 내부 리스너. 한적 인프라를 건드리지 않기 때문이다.

## 9. 평가

`harness/`는 서버를 띄우지 않고 application 층을 직접 불러 돈다.
`harness/scenarios/travel-context-explanation.md`가 이미 규정한 **금지 행동 6종**을
세는 것이 이 하네스의 일차 목적이다.

08-17 §10의 검사 넷(없는 관광지 발명, 코스 순서 변경, LLM이 골랐다는 서술,
인용 유효성)에 이 설계에서 둘을 더한다.

- **고정 데모 코스 도달성** — §7의 uuid 각각이 한적에서 아직 조회되는가
- **프롬프트 결정성** — 같은 입력이 바이트 단위로 같은 `system` 문자열을 만드는가
  (캐시 히트의 전제이며, 어긋나면 비용이 조용히 오른다)

**"LLM이 규칙 기반 템플릿보다 나은가"를 재는 자리이기도 하다.** 한적이 이미
각 항목에 규칙 기반 문구를 붙여 주므로, 같은 facts에 대해 템플릿 문장과 LLM 설명을
나란히 놓고 비교할 수 있다. 이 비교를 배포 전에 한 번 돌린다.

---

## 10. 순서

1. **레포 생성 → `context`·`llm` 패키지와 `harness/`.** 프롬프트를 조립하고 모델을
   부르고 인용을 검증하는 데까지. `presentation` 0줄, `frontend/` 0줄.
   이 단계 끝에 금지 행동 6종을 센다. 위키의 `harness/scripts/explain-spike.sh`가
   여기 뿌리가 된다.
2. **평가 결과로 프로바이더와 `effort`를 확정.** Anthropic 직접이냐 OpenRouter
   무료냐가 여기서 데이터로 갈린다. 바뀌는 것은 `llm` 패키지 하나뿐이다.
3. **`facts`와 `presentation`.** 한적 클라이언트 3회 호출, 엔드포인트 4개, 캐시,
   에러 매핑. Modulith 경계 테스트를 여기서 세운다.
4. **`frontend/` 화면 둘.** 서버 하나만 호출하므로 목킹이 단순하고 한적 없이도
   개발된다.
5. **`infra/`와 배포.** Cloud Run + Vercel.

1번이 먼저인 이유는 바뀌지 않는다. 이 저장소가 존재하는 이유가 "지어내지 않게 하는
것"인데, 그 실패율을 모른 채 프론트까지 지으면 프로바이더를 바꿔야 할 때 버릴 것이
두 배가 된다.

---

## 11. 하지 않는 것

08-17 §12의 목록을 유지하고, 이 설계에서 셋을 더한다.

- 설명 이력 저장 (§6.2 — DB 없음 전제를 깬다)
- 코스 생성 화면 (§7 — 데모 코스 고정으로 대체)
- 한적 프론트엔드 연동 (§1 — 쇼케이스로 규정했다)

---

## 12. 미해결

*상태는 2026-09-01 기준. §10의 1~3단계가 실행됐고 평가가 실제로 돌았다.*

1. **프론트 디자인 시스템.** Next.js는 정했으나 한적의 Astryx를 쓸지 새로 쓸지 미정.
   쇼케이스라면 맞출 이유는 약하다. — **미해결.** 계획 3이 답한다.

2. ~~**레포 공개 여부.**~~ — **해소.** `hyunolike/hermes-agent`를 공개로 만들었다.
   프롬프트가 공개되지만, 번들·픽스처·프롬프트가 모두 이미 공개인
   `travel-context-wiki`에서 생성되므로 새로 노출되는 것은 없다.

3. **프로바이더** — **부분 측정, 여전히 미결.** OpenAI(`gpt-4o-mini`)만 실측했다.
   5회 실행에서 인용 5/5 유효, 금지 행동 6종 위반 0%. Anthropic과 OpenRouter는
   아직 한 번도 돌리지 않았으므로 §6.1의 "Anthropic 직접" 결정은 **근거 없이 서 있는
   상태다** — 그 결정의 논거였던 프롬프트 캐싱은 여전히 측정되지 않았다.
   세 프로바이더를 같은 프롬프트로 돌리기 전에는 §6.1을 다시 쓸 수 없다.

4. ~~**평가가 한 번도 실행되지 않았다.**~~ — **해소.** 실행했고, 그 결과가 프롬프트
   결함 셋을 연달아 드러냈다. 각각 고치고 재측정했다.

   | 발견 | 증상 | 조치 |
   | --- | --- | --- |
   | 인용 형식이 지정된 적 없음 | 5/5 거절. 모델이 번들 본문의 `[[...]]` 위키 링크를 그대로 인용했다 — 형식을 주지 않았고 맥락이 그것만 보여줬다 | 프롬프트에 인용 계약 명시 → 5/5 통과 |
   | 문체가 방치됨 | 한국어 문장 안의 영어 단어, 말한 적 없는 것에 대한 자기참조, 묻지 않은 것에 대한 해명 | `Voice` 절 추가 → 사라짐 |
   | 시간대 혼잡 날조 | "평일 오전 시간대에 여러 사람이 모일 것으로 예상되어" — 시간 축은 계약에서 폐기됐다 | 프롬프트 금지 목록에 추가 → 5회 전부 없음 |

   셋째가 남긴 교훈이 이 문서 밖으로 나갈 만하다: **`concepts/congestion-diagnosis.md`와
   `queries/why-this-place-today.md`가 이미 그 주장을 금지했고 둘 다 번들에 있었는데도
   모델은 날조했다.** 참조 문서는 도메인을 설명하고, 프롬프트의 금지 목록은 모델이
   지시를 받는 채널이다. 규칙이 전자에만 있으면 지켜지지 않는다.

5. **평가가 재지 못하는 축이 있다.** 여섯 검사는 전부 "거짓을 말했는가"를 묻고
   "읽을 만한가"는 묻지 않는다. 실제로 위반 0%인 실행에서 뜻이 통하지 않는 표현
   ("재공급된 혼잡 진단 정보"), 근거 없는 형용("매우 붐비는 매력적인 장소"),
   등급 오역(`NORMAL`을 "정상적인"으로 — 체계는 여유/보통/혼잡/매우혼잡)이 나왔다.
   규칙으로 세기 어려운 종류라 지금은 사람이 본문을 읽는 것으로 대신한다
   (하네스가 설명 본문을 함께 출력한다).

6. **표본이 얕다.** 픽스처 1개, 실행 5회. 드물게 나오는 날조는 이 표본으로 보이지
   않는다. 프로바이더를 결정하기 전에 실행 횟수를 늘리고, 데모 코스 3종(§7)으로
   서로 다른 모양의 코스를 태워 봐야 한다.
